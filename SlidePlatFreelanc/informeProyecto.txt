FASE 1: ESPECIFICACIÓN DE REQUISITOS DEL PROYECTO
1. INFORMACIÓN GENERAL DEL PROYECTO
1.1 Título del Proyecto
Plataforma SaaS para la Gestión Integral de Freelancers
1.2 Resumen del Proyecto
Freelance Flow es una aplicación web desarrollada para facilitar la administración de clientes, proyectos y tareas de trabajadores independientes y pequeñas agencias. La plataforma centraliza toda la información relacionada con clientes y proyectos, permitiendo un mejor seguimiento de actividades, control de tiempos y organización del trabajo.
El sistema proporciona herramientas para registrar clientes, administrar proyectos, organizar tareas mediante un tablero Kanban y visualizar indicadores de productividad mediante un dashboard interactivo.
1.3 Problemática
Actualmente muchos trabajadores independientes utilizan hojas de cálculo, correos electrónicos y aplicaciones dispersas para administrar sus actividades. Esta situación genera:
* Pérdida de información.
* Falta de seguimiento de proyectos.
* Dificultades para priorizar tareas.
* Problemas para medir productividad.
* Baja eficiencia operativa.


1.4 Objetivo General
Desarrollar una plataforma web para la gestión integral de clientes, proyectos y tareas orientada a freelancers y pequeñas agencias.
1.5 Objetivos Específicos
* Centralizar la gestión de clientes.
* Organizar proyectos asociados a clientes.
* Gestionar tareas mediante un tablero Kanban.
* Visualizar métricas de productividad.
* Implementar una API REST para futuras integraciones.

2.5 Caso de Uso Extendido
Gestión de Proyectos
Actor: Freelancer
Precondiciones:
* Usuario autenticado.
* Cliente registrado previamente.
Flujo Principal:
1. El usuario accede al módulo de proyectos.
2. El sistema muestra la lista de proyectos.
3. El usuario selecciona crear proyecto.
4. Ingresa nombre y descripción.
5. Selecciona un cliente.
6. Guarda la información.
7. El sistema registra el proyecto.
8. El proyecto queda disponible para asignar tareas.
Postcondición:
El proyecto se almacena correctamente en la base de datos.
3. ARQUITECTURA DE SOFTWARE
Arquitectura Seleccionada
Arquitectura Hexagonal.
Justificación
La arquitectura hexagonal fue seleccionada porque permite separar la lógica de negocio de los componentes tecnológicos.
Ventajas:
* Independencia del framework Django.
* Facilidad de pruebas unitarias.
* Mantenimiento simplificado.
* Escalabilidad futura.
* Integración sencilla con APIs externas.

CONCLUSIONES
* Se desarrolló exitosamente una plataforma web para la gestión integral de clientes, proyectos y tareas orientada a freelancers y pequeñas agencias, cumpliendo el objetivo general planteado.
* Se logró centralizar la gestión de clientes mediante un módulo que permite registrar, consultar, actualizar y administrar la información de cada cliente de manera organizada.
* Se implementó la gestión de proyectos asociados a clientes, facilitando el seguimiento y control de las actividades desarrolladas para cada uno de ellos.
* Se desarrolló un tablero Kanban para la administración de tareas, permitiendo visualizar y controlar el avance de los trabajos de forma intuitiva y eficiente.
* Se incorporó un módulo de métricas de productividad que proporciona información relevante para evaluar el rendimiento y el estado de los proyectos.
* Se implementó una API REST que permite la integración futura con aplicaciones y servicios externos, garantizando la escalabilidad del sistema.
* La utilización de tecnologías como Django, PostgreSQL y HTMX, junto con una arquitectura hexagonal, contribuyó al desarrollo de una solución robusta, mantenible y escalable.
